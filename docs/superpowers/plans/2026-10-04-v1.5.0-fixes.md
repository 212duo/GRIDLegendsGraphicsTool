# 1.5.0 问题修复实施计划

**目标：** 修复 v1.4.0 审查中确认的写回、预设、线程、写入安全和生命周期问题，发布签名的 1.5.0 APK（PR + Draft Release）。

**基线：** `origin/main` = `3b6be0b`（v1.4.0）。分支：`claude/v1.5.0-fixes`。

**已确认的决策：**

- 编辑页“应用预设”改为直接读取 20 份内置真实 `preferences`，删除公式生成的 8 个预设；“极高(4)”保留为可手动选择的实验档，界面标注风险。
- 发布方式：推送分支并创建 PR；打包 APK 上传为 Draft Release（目标 `main`），由维护者合并 PR 后公开发布。

**验证手段：** 所有数据层修复以 `app/src/main/assets/presets/*/preferences` 中的真实文件做 JUnit 回归测试；UI 与文件访问改动通过编译和 Release 构建验证。真机行为（Root/Shizuku/SAF 写入、游戏读取结果）本次无法验证，需在发布说明中写明。

## 任务 1：写回正确性（#1、#2）

文件：`data/ConfigWriter.kt`、`data/ConfigExporter.kt`、新增 `test/.../ConfigWriterRealFileTest.kt`

- [x] 红灯测试（真实文件 `mid_dedicated`）：
  - 仅修改 `Shadows` 后，重新解析只有 `Shadows` 与 `Graphics/Shadows` 变化，其余字段与原文件一致。
  - 传入全部参数但都未改变时，输出与原文件字节一致。
  - 值与原值相同的字段不会写到其他区块（`BenchmarkSetup`、`BatterySaver`、`Performance` 不变）。
- [x] `replaceValueInBlock` 改为返回 `String?`（`null` 表示未命中），命中即视为成功，不再依赖字符串比较。
- [x] 不限区块的 `<value>` 兜底只用于非注册表格式文件（不存在 `<key name="GraphicsSettings">` 时）。
- [x] `write` 先解析原文件，只写与原值不同的字段；`Graphics` 档位同步只针对实际变化的当前值，且显式提供的档位值优先。
- [x] 新增 `ConfigWriter.renderVerified(existing, values): Result<String>`：渲染后重新解析，校验每个变化字段都已落地，否则返回失败并列出字段；`ConfigExporter` 改用它。
- [x] 保留现有 `GraphicsOptionsTest` 中“修改当前值同步到 Graphics 档位”的语义。

## 任务 2：编辑页预设改用真实文件 + 极高档实验标注（#3）

文件：删除 `data/GraphicsPresets.kt`；新增 `data/PresetApplication.kt`；修改 `ui/screens/EditorScreen.kt`、`data/GraphicsParam.kt`、`data/ParamDefinitions.kt`、`ui/components/ParamRadioGroup.kt`、`GraphicsOptionsTest.kt`

- [x] `PresetApplication.valuesFrom(rawValues)`：取全部可编辑参数，加上 `Graphics/*`、`Performance/*` 档位字段（`BatterySaver` 在 20 份文件中完全一致，不处理）。
- [x] 应用到实时配置时只写入目标文件中已存在的字段，跳过项数用提示告知用户。
- [x] `PresetCard` 列出 `PresetCatalog` 的 20 个预设（按低/中/高/极限分组），通过 `PresetRepository` 在 IO 线程加载。
- [x] `GraphicsParam` 新增 `experimentalValues`；所有含 `4` 的选项标为实验，单选组显示“极高·实验”，选中时显示风险说明。
- [x] 测试：任一真实预设应用到 `mid_dedicated` 基线后写出，重新解析的托管字段与该预设一致；20 份真实文件中不出现任何实验值。
- [x] 删除依赖生成式预设的旧测试 `generatedPresetsSynchronizeRecommendedGraphicsOptions`。

## 任务 3：后台线程与状态保存（#4、#5、#11 中的 logBuffer）

文件：`ui/screens/HomeScreen.kt`、`ui/screens/EditorScreen.kt`、`fileaccess/ShizukuFileOperator.kt`、`fileaccess/RootFileOperator.kt`、新增 `fileaccess/OperationLog.kt`

- [x] 首页：配置检测放入 `withContext(Dispatchers.IO)`；Root 检测、目录诊断改为协程执行并显示“检测中/扫描中”。
- [x] 编辑页：加载、保存、导出构建都在 IO 线程执行，保存期间按钮显示进度且禁止重复点击。
- [x] `logBuffer` 替换为线程安全的 `OperationLog`（有上限，返回快照）。
- [x] 首页 `accessMode` 改为 `rememberSaveable`。

## 任务 4：安全写入、备份轮换与恢复（#6、#7）

文件：`fileaccess/FileOperator.kt`、`fileaccess/ShizukuFileOperator.kt`、`fileaccess/RootFileOperator.kt`、新增 `fileaccess/ConfigBackups.kt`、`ui/screens/EditorScreen.kt`

- [x] Root/Shizuku：base64 分块写入临时文件 → 解码到临时文件 → 成功后再覆盖目标 → 读回比对内容；任何一步失败都不动原文件，并清理临时文件。

- [x] 写入前统一用 `ConfigWriter.renderVerified` 校验，校验失败不写入并提示具体字段。
- [x] 备份命名不变，保存后只保留最近 5 份 `preferences_backup_*`（只清理本工具创建的文件）。
- [x] 编辑页顶栏新增“恢复备份”：列出备份（时间倒序）→ 确认 → 写回并重新加载。
- [x] “恢复默认”改名为“撤销未保存修改”。
- [x] 测试：备份文件名解析、排序与保留策略的纯函数单测。

## 实施记录

- 任务 1–6 全部完成；单元测试由 21 个增至 41 个，全部通过。
- 实施中的补充决定：
  - 备份创建失败时取消保存（v1.4.0 会忽略备份失败继续写入）。
  - Root 文件操作只读取标准输出，避免 `su` 输出到 stderr 的提示混入配置内容、导致读回校验失败。
  - 注册表格式文件中，`BatterySaver`/`BenchmarkSetup` 等区块的值不再被解析为当前值。
  - 内置预设通过 `.gitattributes` 标记为二进制，防止换行符转换改动文件。
- Release APK：versionCode 10 / 1.5.0，v2 签名校验通过，证书与历史版本一致；APK 内 20 份预设与源文件逐字节一致。
