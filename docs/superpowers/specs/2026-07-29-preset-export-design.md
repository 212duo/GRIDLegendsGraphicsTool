# 内置画质预设编辑与导出设计

## 1. 状态与目标

- 设计日期：2026-07-29
- 设计状态：用户已确认
- 目标：让无法完成游戏目录授权的用户，也能基于 App 内置的真实画质配置进行修改，并导出可手动安装的 `preferences` 文件。

用户提供的 `D:\download\极限画质（高中低）` 中包含 20 份实际使用的 `preferences` 文件。检查结果表明这些文件都是合法 XML，每份约 37 KB，拥有相同的主体注册表结构，并包含两种相近的字段版本。它们比当前 `GraphicsPresets` 中的 51 个参数映射更完整，适合作为导出的权威基线。

## 2. 背景问题

当前产品只有在 SAF、Shizuku 或 Root 成功读取游戏配置后才能进入编辑器。很多用户卡在游戏目录授权，因此即使只想取得一份预设文件，也无法使用 App。

仓库已经具备以下可复用能力：

- 解析完整 `preferences` 文件；
- 基于原始文件定点替换画质参数；
- 使用 Compose 编辑画质参数；
- 在直接修改游戏配置时创建备份并写回文件。

当前 `ConfigWriter.generateFreshConfig` 不能作为本功能的文件来源。它只生成部分区块，会遗漏 `Graphics`、`Performance` 及大量非托管字段。新功能必须以真实完整文件为基线，不能从当前代码中的参数表重新拼装配置。

## 3. 范围

### 3.1 本期包含

- 将 20 份真实 `preferences` 文件复制为 App 内置资源；
- 提供无需任何游戏目录权限的预设库入口；
- 将 20 个预设按低配、中配、高配、极限四组展示；
- 从任一预设进入编辑器并修改现有可编辑参数；
- 将未修改或修改后的配置导出为文件名严格为 `preferences` 的文件；
- 导出完成后展示手动复制路径和安全提示；
- 保留现有 SAF、Shizuku、Root 直接编辑流程。

### 3.2 本期不包含

- 自动把导出文件复制到受保护的游戏目录；
- 绕过 Android 存储限制；
- 用户自建、收藏或同步预设；
- 根据手机硬件自动推荐预设；
- 分享到社交应用或生成压缩包；
- 扩充现有画质参数定义；
- 将手工页面路由迁移到 Navigation Compose。

## 4. 方案选择

### 4.1 采用方案：每个预设内置完整文件

每个预设保留一份完整的真实 `preferences` 文件。用户选择预设后，编辑器读取完整内容；导出时只替换用户修改的字段，其余字段原样保留。

选择理由：

- 真实文件已经过实际使用，可靠性高于代码生成；
- 不需要推断两种文件版本之间的差异；
- 不会遗漏两百多个未纳入 App 参数模型的字段；
- 20 份文件合计约 740 KB，APK 体积成本可接受；
- 单个预设可以独立替换或下架，维护边界清晰。

### 4.2 未采用方案

1. 单一完整模板加 20 份差异：体积略小，但需要维护差异合并规则，容易漏掉关联参数或文件版本差异。
2. 根据参数映射从零生成：体积最小，但现有生成器结构不完整，游戏兼容风险最高。

## 5. 用户流程

### 5.1 首页入口

首页保留现有的“直接修改游戏配置”能力，并新增主要入口：

> 从预设制作画质文件

该入口不依赖以下任何条件：

- 游戏是否已安装；
- SAF 是否已授权；
- Shizuku 是否安装或运行；
- 设备是否具有 Root 权限。

这样，授权失败或只想提前制作文件的用户仍可完成完整流程。

### 5.2 预设库

新增 `PRESET_LIBRARY` 页面。页面按以下固定顺序分组，组内从相对保守到相对激进排列：

#### 低配（7）

1. 极低专属
2. 极低120帧
3. 超低配专属
4. 超低配120帧
5. 低配专属
6. 低720p+60帧（无观众）
7. 平衡优化版（低功耗）

#### 中配（3）

1. 中配专属
2. 极致平衡（中配专属）
3. 平衡画质

#### 高配（5）

1. 高配专属
2. 极致优化（70帧）
3. 极致优化（90帧）
4. 极致优化平衡（高配）
5. 高配专属1080p120帧

#### 极限（5）

1. 超极限2k+30帧
2. 超极限画质2K+120帧
3. 超越极限（最终版）
4. 超越极限（最终版120帧）
5. 超越极限最终版120帧HDR（仅限支持HDR使用）

每个预设卡片展示：

- 原始预设名称；
- `PresetRepository` 从文件解析出的分辨率、帧率、HDR 标签；
- 简短的适用设备说明；
- “基于此预设编辑”按钮。

第一版不提供搜索、收藏和自动推荐。20 个条目通过分组已经能够有效浏览。

### 5.3 编辑器

编辑器支持两种明确的来源：

1. `LiveConfig`：从 SAF、Shizuku 或 Root 读取的游戏配置；
2. `BundledPreset`：从内置资源读取的完整预设。

预设导出模式的界面规则：

- 标题为“制作画质文件”；
- 顶部展示当前预设名称和关键标签；
- 不显示现有的预设下拉卡，避免在编辑过程中隐式切换基线；
- “恢复默认”恢复到所选内置文件的原始值；
- 底部“导出 preferences”按钮始终显示，即使用户尚未修改任何参数；
- 有未导出修改时返回上一页，弹出放弃修改确认。

直接游戏配置模式保持现有标题、预设卡和“保存设置”行为，不改变原有授权与写回流程。

### 5.4 导出与安装提示

点击“导出 preferences”后，使用 Android 系统文件保存器：

- MIME 类型使用 `application/octet-stream`，避免文件提供器自动添加 `.xml`；
- 建议文件名为 `preferences`；
- 用户可保存到下载目录或其他可访问位置；
- 用户取消系统保存器时，不提示失败，也不改变编辑状态；
- 覆盖同名文件的确认由系统文件保存器处理。

导出成功后显示以下说明：

> 已导出 preferences。请先关闭游戏并备份原文件，再使用文件管理器将导出文件复制到：
> `Android/data/com.feralinteractive.gridlegends_android/files/feral_app_support/preferences`

App 不宣称已自动安装配置，也不尝试再次申请游戏目录权限。

## 6. 架构与组件

### 6.1 资源目录

预设存放在：

```text
app/src/main/assets/presets/<preset-id>/preferences
```

`preset-id` 使用稳定的 ASCII 标识符，展示名称保存在元数据中。导入时只复制源文件，不修改 `D:\download\极限画质（高中低）` 中的原始文件。

### 6.2 `PresetCatalog`

职责：声明固定的 20 个预设及展示顺序。

每个 `PresetMetadata` 至少包含：

- `id`；
- `name`；
- `group`；
- `description`；
- `assetPath`；
- 用于展示的标签。

目录元数据不保存整套画质参数值。完整文件才是参数的权威来源，避免 Kotlin 参数表与真实文件发生漂移。

### 6.3 `PresetRepository`

职责：

- 从 assets 读取预设的原始字节和 UTF-8 内容；
- 使用 `ConfigParser` 解析可编辑参数；
- 校验 XML 可解析且包含全部 `ParamDefinitions.allParams` 对应字段；
- 向 UI 返回成功结果或中文错误信息。

仓库不负责 Compose 状态、文件导出或游戏目录写入。

### 6.4 `EditorSource`

使用明确的会话来源替代 `configPath`、`configContent`、`accessMode` 多个可空参数共同推断模式。建议结构：

```text
EditorSource
├── LiveConfig(accessMode, configPath, configContent)
└── BundledPreset(presetId, baseBytes, baseContent)
```

`MainActivity` 继续使用现有手工路由，但新增 `PRESET_LIBRARY`，并保存当前 `EditorSource`。本功能不引入新的导航框架。

### 6.5 `ConfigExporter`

职责：接收预设原始内容和当前参数，构建并校验待导出数据。

规则：

1. 未修改任何参数时，直接返回资源的原始字节，保证导出文件与内置预设逐字节一致；
2. 有修改时，调用 `ConfigWriter.write(..., existingContent = baseContent)` 定点替换；
3. 在内存中重新调用 `ConfigParser` 解析生成结果；
4. 验证每个已修改字段都等于目标值；
5. 只有全部验证成功，才允许写入用户选择的 URI。

这样可以发现 `ConfigWriter` 未匹配目标字段但没有抛出异常的情况，防止导出“看似成功、实际未修改”的文件。

## 7. 数据流

```text
首页
  → 预设库读取 PresetCatalog
  → 用户选择 preset-id
  → PresetRepository 读取并校验完整 preferences
  → ConfigParser 生成编辑器参数
  → 用户修改 ParamValue
  → ConfigExporter 基于原始文件生成并复核结果
  → 系统文件保存器返回目标 URI
  → ContentResolver 写入 preferences
  → 显示手动安装说明
```

预设原始字节在整个编辑会话中保留，用于未修改时的精确导出和“恢复默认”。未展示、未管理的字段始终来自所选真实文件，不经过重新生成。

## 8. 错误处理

### 8.1 预设读取失败

资源缺失、UTF-8 解码失败、XML 无法解析或缺少必要画质字段时：

- 阻止进入编辑器；
- 显示具体的预设名称和失败原因；
- 允许返回预设库选择其他文件。

### 8.2 内容生成失败

生成结果无法解析，或修改字段复核失败时：

- 不启动或不执行最终写入；
- 保留用户当前编辑状态；
- 提示“导出内容校验失败，请更换预设或恢复后重试”。

### 8.3 文件写入失败

目标 URI 无法打开、权限被撤销或存储空间不足时：

- 显示系统异常的简化中文信息；
- 不把当前状态标记为已导出；
- 允许用户重新选择保存位置。

### 8.4 用户取消

取消系统保存器属于正常操作，不显示错误 Toast，也不丢弃编辑内容。

## 9. 兼容性与安全

- 最低 SDK、目标 SDK 和现有依赖不变；
- 导出到普通目录只使用 SAF 创建单文件，不申请广泛存储权限；
- 预设入口不调用 Root、Shizuku 或游戏目录 SAF；
- 文件名保持无扩展名的 `preferences`；
- HDR 预设明确保留“仅限支持 HDR 使用”警告；
- 安装提示要求先关闭游戏并备份原文件；
- 现有直接写回流程仍负责自己的备份，导出流程不操作游戏原文件。

## 10. 验收与验证

项目没有自动化测试套件，本功能按仓库约定使用 Gradle 构建与人工场景验证。

### 10.1 构建验证

```bash
./gradlew assembleDebug
```

命令必须成功退出。

### 10.2 资源验证

- `PresetCatalog` 恰好包含 20 个唯一 ID；
- 四个分组数量分别为 7、3、5、5；
- 每个元数据路径均能读取对应 asset；
- 20 份 asset 均能被 `ConfigParser` 解析；
- 每份 asset 均包含全部可编辑参数。

### 10.3 人工场景

1. 未安装游戏、未授权 SAF、未安装 Shizuku时，仍能进入预设库；
2. 四个分组和 20 个预设全部显示，顺序与本规格一致；
3. 选择任一预设后能进入编辑器并看到正确的帧率、分辨率和 HDR 状态；
4. 不做修改直接导出，导出文件与内置 asset 的哈希一致；
5. 修改帧率、分辨率和至少一个开关后导出，重新解析确认目标字段已变化，其他未托管字段未变化；
6. 系统文件保存器建议名称为 `preferences`，文件没有 `.xml` 扩展名；
7. 取消导出后编辑内容仍在；
8. 模拟不可写位置或写入异常时显示错误且可以重试；
9. 现有 SAF、Shizuku、Root 进入编辑器及保存流程仍能正常使用；
10. 导出成功提示包含准确的目标路径和备份提醒。

## 11. 完成标准

满足以下全部条件才视为实现完成：

- 用户无需游戏目录权限即可从 20 个真实预设中选择并编辑；
- 未修改时精确导出原始预设，修改时只替换目标字段；
- 导出文件名为 `preferences` 且能被现有解析器重新读取；
- 用户获得清晰的手动安装与备份提示；
- 原有三种直接访问模式没有行为回归；
- Debug APK 构建成功并完成上述人工场景验证。
